# When to Use Skills

When you reach for each skill in how you work, including when nobody asks. A skill's own
description says what it does; this says when you use it.

**Belongs here:** one line per situation, situation first, then the exact, fully qualified
skill name. `<skill>.md` only for nuance that doesn't fit on a line.

**Doesn't belong:** what a skill does or how it works (the skill itself), a skill's bugs or
gaps (fix the skill in the toolkit), the stage sequence inside the orchestrated flow (the
flow skill owns it).

## Entries

- **Writing or changing any code, however small** → `coding-standards:coding-standards`
- **Just before opening a PR, on your branch** → `code-review:code-review`
- **Asked to review someone else's PR** → `code-review:code-review`
